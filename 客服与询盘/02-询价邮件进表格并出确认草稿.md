# 询价邮件进表格，并出确认草稿（n8n，不发信）

## 场景

询价邮件进来以后，先做三件事：把客户、产品、数量、送货地和希望交期抽成一行，写进表格，再回一封「请先确认这些信息」的草稿。这一步还不报价，避免抽错字段或报错价格。

这是本机演示，没有连接任何真实邮箱，也不会发信。

## 用什么工具

- 自托管 n8n（演示时用过 2.48.7，本机安装，只监听 127.0.0.1）
- 工作流文件：[`tools/n8n/inquiry-to-sheet.json`](../tools/n8n/inquiry-to-sheet.json)
- 一次成功执行留下的示例结果：[`tools/samples/示例询价表格.csv`](../tools/samples/示例询价表格.csv)、[`tools/samples/示例询价确认草稿.txt`](../tools/samples/示例询价确认草稿.txt)

不需要 API key。工作流里如果有「用模型润色草稿」的节点，应保持关闭，除非你自己愿意接钥匙，并且仍然只生成草稿。

## 具体步骤

1. 在本机安装并启动 n8n，不要把它暴露到公网，也不要在第一次演示时登录真实 Gmail 或 Outlook。
2. 导入 `tools/n8n/inquiry-to-sheet.json`。如需改保存位置，把写入节点里的路径改成你本机的 `./output/`，并先建好这个目录。
3. 用「手动触发」跑一遍。没有传入邮件正文时，工作流会使用内置的虚构询价（一家虚构咖啡店询问燕麦奶和咖啡豆的价格与起订量）。
4. 当前抽取靠正则和关键字，不是大模型。换一种写法的邮件，可能抽不全或抽错，所以草稿里必须请对方确认，并且不填写价格或起订量。
5. 打开输出的 CSV 和 `draft-reply.txt`，检查字段是否正确。只有你确认无误，才考虑把草稿复制到自己的邮箱里发送。
6. 以后如果要接真实邮箱：只申请「读邮件」或「创建草稿」权限，不要开「发送」。触发器换成 Gmail / Outlook / IMAP 之后，后面「抽字段 → 写表 → 出草稿」可以继续用，但解析规则通常要按你店里的常见问法改一版。客户邮件是隐私数据，存放和备份要先想清楚。

## 可复制提示词或配置

工作流主路径：

1. Manual Trigger（手动触发）。Webhook 节点如果存在，默认应保持禁用，避免误开对外接口。
2. Prepare Input：有传入正文就用传入的，否则用内置示例。
3. Parse Inquiry：抽取客户名、产品、数量、送货地址、希望交期。
4. 写成 CSV 并写到磁盘。
5. Draft Reply：生成一封待发送的确认草稿，明确写「还没有发出」，不写价格或起订量。

演示里跑出来的确认草稿大意是：

- 记下产品、数量、送货地址、希望交期
- 请对方先确认有没有漏或写错
- 正式报价要对照当天库存和物流后再给，这里先不写价格
- 标明这是待发送草稿，还没有发出

把真实邮件接进来之前，解析规则和草稿语气都要按你的店改过，并再跑几封历史邮件做对照（先脱敏）。

## 注意事项

- 不要自动发信，不要自动报价。发错价格或承诺做不到的交期，责任在店，不在工具。
- 简单规则会误判。草稿必须人看。
- n8n 是工具，不是已经卖得出去的成品。要给别的店用，还要改流程、教使用、处理托管和备份。
- 本机演示不能当成已经加固的生产环境。若以后放到服务器上，还要处理 HTTPS、登录、更新和客户数据存放。
- 工作流 JSON 里的示例咖啡店、地址和邮箱都是虚构的，请勿发信。
