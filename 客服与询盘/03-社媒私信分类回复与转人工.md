# 社媒私信分类：常见问题出草稿，投诉和订座转人工

## 场景

小店的 Facebook、Instagram 或同类私信里，经常会问营业时间、能不能带狗、有没有素食、怎么停车。这类问题可以用一份店主核实过的店铺资料，生成回复草稿。订座、包场、投诉、退款，以及任何资料里没有写过的问题，应转给店长，不要让程序自己编。

这一条是本机分类演示，用的是假消息和占位符店铺资料，没有接到任何真实主页。

## 用什么工具

- 本机 n8n（与询价工作流同一类工具即可），或先把规则做成一张表，在对话工具里手动套
- 一份只有店主确认过的店铺资料：店名对外怎么写、营业时间、宠物规则、素食或过敏原、停车。没有核实过的，不要写进自动草稿

本仓库不提供连接到 Facebook 或 Instagram 的现成接口配置。没有店主授权和真实资料之前，不要去接真实账号。

## 具体步骤

1. 请店主用书面方式确认店铺资料。营业时间、能不能带宠物进店、菜单是否真有某类选项，都不能猜测，也不能沿用旧海报。
2. 先定两类规则。一类是「资料里有、可以起草回复」的常见问题；一类是「必须转人工」的情况。
3. 用若干条假消息先跑分类：看它会不会把投诉或订座误当成常见问题，会不会把没写过的问题（例如礼品卡）自己编一个答案。
4. 只有分类稳定、而且每条自动草稿都能在店铺资料里找到依据，才考虑下一步怎么接到真实收件箱。接到以后，仍然建议先写进「待店长确认的草稿」，不要直接公开回复。
5. 投诉到达时，先给顾客一句「已转给负责人，会尽快亲自回复」，同时给店长一条提醒。不要在自动草稿里道歉认责、承诺退款或解释事故经过。

## 可复制提示词或配置

把下面的占位符改成店主确认过的原文。方括号里的字是提示，不要原样发给顾客。

```
店铺资料（必须全部由店主确认后再启用）：
- 对外店名：【店主确认】
- 营业时间：【店主确认，区分平日和周末】
- 宠物：【例如：户外座位是否欢迎狗狗、是否提供水碗、能不能进室内】
- 素食 / 无麸质：【有就写有，没有就写没有，不要发挥】
- 停车：【店主确认】

判断规则：
1. 先看是不是投诉、退款、食物质量、态度问题，或订座 / 包场 / 生日聚会。只要命中，一律转人工。给顾客的回复只说：消息已转给负责人，会尽快亲自回复。不要解释事件，不要承诺退款。
2. 再看是不是营业时间、宠物、素食或过敏原、停车。只有资料里写过的，才按原文起草回复。
3. 其余一律转人工，回复「我们会尽快回复」，不要猜测。

请对下面这条顾客消息分类，并给出：意图、由 AI 起草还是转人工、给顾客的草稿、给店长的提醒（如需）。
顾客消息：
【粘贴在这里】
```

演示时用过的分类口径（关键字可按你的店增减，先用英文和中文常见说法）：

- 可起草：hours（open / close / hours / 营业 / 开门 / 关门）；pets（dog / pet / 狗 / 宠物）；veg（vegan / vegetarian / gluten / 素 / 麸质）；parking（park / parking / 停车）
- 必须转人工：complaint（cold / rude / refund / complain / wrong order / disappointed / 投诉 / 退款 / 难吃）；booking（book / reserve / table for / party / birthday / 订座 / 包场 / 订桌）；以及资料里没有的任何问题

一次演示用了 6 条假消息，结果是：营业时间、宠物、素食这 3 条被归为可起草；12 人生日订座、咖啡冷且订单错误的投诉、问是否卖礼品卡这 3 条被转人工。这只说明规则在这 6 条上能分开，不说明接到真实主页以后仍然够用。

## 注意事项

- 未核实的营业时间和菜单，不能写进回复。占位符必须先换成店主确认的原文。
- 不要自动公开回复。过敏、投诉、退款争议，自动回复可能把事情闹大。
- 不要把真实主页的登录方式、令牌或顾客对话写进仓库。
- 关键字匹配会误判，也容易漏掉换一种说法的提问。上线前多用店里以前的真实问题做脱敏测试。

## 真实程度（已实测，有范围）

已用 6 条假消息和占位符店铺资料，在本机把「常见问题起草 / 投诉与订座转人工」跑通。未接真实 Facebook 或 Instagram 主页，未使用真实顾客对话，示例营业时间和菜单未作为事实使用。要接到真实主页，还需要店主提供核实过的资料，以及相应权限；在此之前不要把它写成「已经在店里用起来了」。
